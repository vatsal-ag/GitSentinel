Frequently Asked Questions

Technical details on GitSentinel's behavioral telemetry engine.

How does it catch mutated malware without signatures?

Attackers frequently mutate source code or change hashes, but they cannot hide operating system behavior. A ransomware must perform rapid file modifications; an AI escape must touch host sockets; a worm must scan ports. GitSentinel matches these immutable behavioral patterns.

Does GitSentinel slow down developer builds?

No. GitSentinel runs entirely in user-space using non-blocking stream filters (macOS log stream and Windows Sysmon). It consumes <0.5% CPU and ~40MB RAM.

What happens when a threat is flagged?

GitSentinel displays an instant desktop alert detailing the offending PID, command line, and ancestor process tree. In Active Defense mode, it sends SIGSTOP or SIGKILL to freeze the process before completion.

Can it monitor remote devices or mobile phones?

Yes. GitSentinel serves a secure REST API and responsive PWA web client, allowing authorized access over your local network or private VPN.

Privacy & Local Telemetry Notice

GitSentinel operates with 100% local processing. We use only essential cookies to preserve your threat filter preferences. No personal telemetry is exported.

Privacy Policy & GDPR Disclosure

1. Data Minimization & Local Processing (GDPR Art. 5 & 6)

GitSentinel operates strictly on a local-first paradigm. System log telemetry ingested from macOS Unified Logging, Windows Event Logs, and Linux auditd is processed entirely within local memory and committed exclusively to your local SQLite database (sentinel.db). No process trees, command lines, or telemetry are transmitted to external servers.

2. User Rights & Data Erasure

You retain absolute ownership of all logged forensics. At any time, you can purge the local audit history by deleting sentinel.db or via the EDR dashboard settings.
